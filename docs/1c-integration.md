# Интеграция Альфинатора с 1С: справка для карты архитектуры

Состояние на 27 ноября 2026 года. Документация пилота; не исходный код расширения и не свидетельство полной production-приёмки.

## Компоненты

- **«Нейро-помощник»** — HTML-чат в управляемой форме 1С.
- **Расширение `НейроИнтеграция`** — метаданные, разрешённые чтения и операции с объектами, подготовка и проверка документов, создание/проведение с подтверждением, открытие карточек и отчётов.
- **Информационная база 1С** — бизнес-объекты, права пользователей, история чатов и настройки подключения.
- **Сервер-посредник** — отдельный от OpenWebUI сервис, готовящий контекст модели и проверяющий структурированные ответы; API лицензирования и обмена заданиями.
- **Администрирование и хранилище лицензий** — лицензии баз, рабочие места и учёт использования интеграции.

## Подтверждённый маршрут посредника

Пользователь 1С → HTML-чат → расширение → HTTPS → посредник → API портала → OpenWebUI.

На развёрнутом сервере прочитана фактическая версия `server.py`, сервис проверен как активный. Функция `alfinator_answer()` вызывает `portal_api('/api/chat/completions', ...)`, а `portal_api()` создаёт HTTP-запрос к публичному адресу корпоративного OpenWebUI. Создание контекста чата использует `/api/v1/chats/new`.

Это проверка развёрнутого кода и состояния процесса, без выполнения новой операции над бизнес-данными. Прямой вызов LiteLLM вместо OpenWebUI для этой функции не используется.

Продолжение цепочки **OpenWebUI → LiteLLM → Privoxy → LLM** отражается согласно документации и фактическим подключениям самого портала. Отдельная сквозная проверка списания бюджета реальным клиентом 1С в рамках этой сверки не выполнялась.

Модель возвращает текст либо описание следующей операции. Расширение выполняет разрешённое чтение, возвращает данные через посредник, и модель формирует следующий шаг или итоговый ответ. Создание и проведение требуют проверки и подтверждения пользователя. Отчёты и карточки открывает клиент 1С; модель не подключается к СУБД напрямую.

## Лицензии и бюджет

Один пользователь 1С соответствует одному рабочему месту. На одну лицензию используется один API-токен портала независимо от количества рабочих мест. Проверки лицензии и рабочих мест выполняются серверным кодом.

Лицензирование интеграции и денежный бюджет LiteLLM — разные механизмы. По действующей документации портала общий токен относит расход на общего плательщика/владельца токена. Это не персональные бюджеты сотрудников 1С. Для учёта использования интеграции важен полный цикл обращений к модели.

Маршрут 1С не следует включать в подтверждённый первый контур обезличивания: по документации портала он вынесен за его рамки.

## Статусы сценариев и конфигураций

| Сценарий / конфигурация | Как обозначать на карте |
| --- | --- |
| Чат из сеанса 1С через расширение и посредник | Работающий пилот; маршрут посредника проверен на развёрнутом коде |
| УНФ | Внутренний локальный тестовый стенд; в ходе разработки проверялись чтения, документы и работа форм. Это не полная совместимость со всеми версиями УНФ |
| БП и УТ | Были отдельные удалённые пользовательские испытания и обратная связь; текущая сквозная приёмка конкретных баз в этой сверке не подтверждена |
| OpenWebUI Tool → 1С из веб-чата портала | Пилот / статус актуального Tool требует проверки. Действующий Tool и его точное актуальное имя этой сверкой не подтверждены |
| Веб-публикация 1С со служебным пользователем, без открытого сеанса пользователя | Планируемый вариант; не обозначать как подтверждённый рабочий маршрут |

Для удалённых БП/УТ не подтверждено, является ли конкретная установка внутренним стендом или клиентским пилотом. Не обозначать их как продуктивные клиентские внедрения без отдельного подтверждения владельца.

## Правила публичной карты

Использовать обобщённые подписи: «HTTPS», «API портала», «Активация», «Проверка лицензии», «Запрос помощника». Допустим публичный контракт OpenWebUI `POST /api/chat/completions`.

Не публиковать адрес посредника, внутренние домены, административные URL, коды лицензий, идентификаторы пользователей/баз и секреты. Конкретные внутренние пути посредника для понимания карты не нужны.

Для внешних узлов оставлять `paths` пустым, если исходники не входят в репозиторий карты. Эту справку указывать через отдельное поле внешних ссылок, например `externalRefs`, с подписью «Документация пилота интеграции 1С». Не выдавать её за репозиторий исходников.

HTML-демка и продающий лендинг не являются рабочими компонентами интеграции.
